# Derived-mapping salience calibration — results

The screen did not reach its intended retention question. All six explicit-control members and all six consequences-only members read and closed the four rule files, which immediately triggered source removal and transcript loss. None read `/work/query` before that boundary, so none reached the predeclared opportunity criterion. No member created a non-answer support file, reread one after the boundary, wrote an exact answer, or submitted `done`.

| Arm | Members | Opportunity reached | Support at boundary | Support reread | Exact task success |
| --- | ---: | ---: | ---: | ---: | ---: |
| Explicit positive control | 6 | 0/6 | 0/6 | 0/6 | 0/6 |
| Consequences only | 6 | 0/6 | 0/6 | 0/6 | 0/6 |

The surprise is that the explicit instruction did not get as far as a storage choice. The common trajectory treated the rule files as the first work, closed the fourth, and thereby crossed the automatic checkpoint before acquiring the query. After the transcript and rules disappeared, it searched for the removed source until the action budget expired. The same pattern occurred across both arms at temperature zero; that repetition records this model/server path, not a general claim about seed effects or prompt wording.

This is a failed task-interface calibration, not evidence that the model does not retain derived state or that explicit instruction cannot elicit it. The task's source-removal trigger is coupled to closing all rule files, while opportunity requires the query to be acquired beforehand. A future task would need a separately frozen checkpoint condition that permits the full prerequisite state to be acquired before source removal. Do not repair these completed members or use them as Pilot 1 evidence.

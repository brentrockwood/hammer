## Forensic reading

At each declared checkpoint, the harness retained exactly 12 complete action/result exchanges (24 messages): steps 59–70 at checkpoint 1 and steps 129–140 at checkpoint 2. The retained material was delivered verbatim; no host-generated summary supplied the omitted history.

Immediately after checkpoint 1, the model opened `/work/answer` (turn 71) and wrote a six-node route (turn 72). That route did not start at the fixture entry, so it was not a valid answer. It then attempted the `answer: done` terminal action on every turn from 74 through 140; each attempt was rejected because the second declared checkpoint had not yet occurred. After checkpoint 2, it resumed filesystem reads rather than reading or revising `/work/answer`. The file remained the only model-created object at the final snapshot, and no observed action reused it.

Relative to the paired H0 trajectory, H12 produced external filesystem state while H0 made no write attempt. This single-seed difference is an observation, not evidence that retaining a 12-exchange tail caused the write or that the written file was a persistent instrumental structure. The retained window also contained recent adapter feedback and potentially live descriptor state, so it is not a filesystem-persistence-only condition.

## Interpretation

This is one exploratory continuity-window treatment. The trace establishes the creation and non-reuse of one invalid candidate answer in this trajectory, but one trajectory per condition cannot establish a causal effect or behavior under uninterrupted full context. Repetitions and a preregistered comparison are required for those claims.
